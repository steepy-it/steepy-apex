# Project — Inception Record

> Structure for the approved project inside one inception run. Fill every section for this
> project; this is not a technology catalog and it does not prescribe a document count.

## Materials, facts, and simulations
(What the run started from: supplied materials, verified facts, and any simulated or assumed
inputs — kept distinguishable from one another.)

## Constraints
(Hard constraints on the project — technical, product, or environmental — plus the stack
preferences per layer (known, preferred, avoided) and the version policy: latest stable,
conservative LTS or N-1, or per layer.)

## Alternatives and reasons
(For each applicable decision category: the options considered, how it was decided — asked,
grouped default, or not applicable with its reason — and why each option was accepted or
rejected.)

## Components, data, and contracts
(The real components, data shapes, and contracts the project is built from or against.)

## Official research
(Each foundational technology choice: official source, explicit version, verification date, and
documented compatibility with the rest of the combination. Then the confirmed version review:
one table per layer with component, chosen version, latest stable version, support status or
end of life, the reason when the choice is not the latest or departs from the version policy,
and source and date.)

## Reused assets and preserved behaviors
(Existing assets carried into the project and behaviors that must keep working unchanged.)

## Representative path
(The one path through the project that the verification record actually exercises.)

## Evidence and chosen deploy
(The evidence gathered for the representative path, and the deploy choice — included or
explicitly excluded — with its reason.)
