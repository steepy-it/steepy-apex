# scripts — Technical Standard

> Owning surface: `scripts`. Read this before editing `scripts`.

## Scope
- Owns: the Node engine scripts under `scripts/` — stack detection, scaffolding, rendering, the hub linter, hooks, release tooling, and workflow controllers; pure exported logic plus thin CLIs.
- Does NOT own: emitted markdown (→ `templates`), exercising suites (→ `tests`), or invoking skill prose (→ `skills`).
- Exemplar: `scripts/validate-hub.mjs`
- Per-script responsibilities are tabulated in [docs/architecture.md → scripts](../../docs/architecture.md).

## Conventions
- Zero runtime/dev dependencies — Node built-ins only. Version operations use shared canonical safe-integer X.Y.Z comparison: no leading zeroes, invalid values, downgrades or equal required increments. `bump-version.mjs` provides recoverable per-file atomicity with exact bytes/modes, complete staging, one durable journal and the existing cooperating-writer scaffold lease. Interrupted retries finish the same target; unexpected edits block without overwrite. Explicit completed targets are manifest-write-free no-ops, not fresh increments. File/directory fsync and atomic rename support are required; `--check` rejects any incomplete transaction. No multi-file or adversarial-filesystem atomicity is claimed.
- ESM, Node >= 24; pure exported functions + a thin `main(argv)` guarded by the `import.meta.url` entry check — precisely true of `new-surface.mjs`, `render-claude-md.mjs`, `validate-hub.mjs`. Exceptions: `sanitize.mjs` / `template.mjs` are shared modules with no CLI; `detect-stack.mjs`'s `main()` is unexported and takes no argv; `stop-hook.mjs` has no `main()` and runs at module top level.
- `validate-hub.mjs` exits 0 (coherent/no-hub) or 1 (violations); never exit 2 — blocking is owned by the hooks: `stop-hook.mjs` (hub violations) and `push-version-guard.mjs` (unbumped pushes to main).
- `validate-hub.mjs` violations carry a `level`: `error` (exit-code-affecting) or `warn` (informational only, e.g. a `standards/**/*.md` file over `STANDARD_WARN_LINES` lines — a candidate for the modular folder form). Warns print in non-`--quiet` runs; `--quiet` (the Stop hook) never prints them, keeping it a no-op on warn-only hubs. Stable hub reads accept physical ordinary files only, validate native path components before parent traversal, bind verified descriptors, and remain bounded; they never follow a descendant symlink into `.apex/work` or an external path. The exact repository `.apex` entry may be a relative or absolute directory symlink to an external hub: bind its physical target once, retain logical repository-relative paths for links and graph identities, and keep repository code/provider checks rooted in the repository. Broken, cyclic, unreadable, and non-directory hub mounts are controlled errors, not absent hubs. The reserved `.apex/work` directory is bound by physical identity before descendant enumeration, inspection, or reads: a case alias that resolves to that identity is excluded, while a physically distinct namesake on case-sensitive storage remains stable content. Hub root admission rejects unsupported parent traversal and a direct root symlink before establishing one physical identity for every caller. A failed candidate read is a controlled error, not absence; `package.json` unsafe reads are a controlled error, while genuinely absent or safely read malformed package metadata retains the optional npm-validation behavior. A terminal separator or dot preserves its directory requirement. Reverse routing recognizes only canonical provider agent identities and reports every nested namesake with its required top-level path.
- Code-anchor checks 9–12 keep stable docs honest about the codebase, and all four are skip-if-absent: an absent anchor is never a violation, only a present-and-dead one is (a nonconforming shape is skipped the same way). Check 9 (`warn`; promotion deferred pending field experience) scans stable `.apex/**/*.md`, root `AGENTS.md`/`CLAUDE.md`, and `.claude/agents/*.md` for backtick tokens that pass the strict-shape rule (`isCheckablePathToken`: contains `/` and no glob, placeholder, inline-command, ellipsis, flag, URL, absolute-path, or backslash marker — excluded by shape, never by allowlist) yet resolve at none of three roots (repo root, the citing doc's directory, `.apex/`): `code-anchor: <doc> cites missing path: <token>`.
  Check 10 (`error`): every top-level single-file standard (`.apex/standards/*.md`) and modular core (`.apex/standards/**/*-core.md`), selected by file shape regardless of routing membership, whose `Owning surface:`/`Owning path:` header value is not a directory at the repo root — `code-anchor: <doc> owning-surface directory does not exist: <value>`. Check 11 (`error`): in those same shape-selected standards' `## Testing` sh blocks, a path-shaped token missing from the repo root — `code-anchor: <doc> Testing command cites missing path: <token>` — or an invoked script absent from the repo-root package.json — `... references missing npm script '<name>'` (no package.json skips only the npm half).
  Check 12 (`error`): root `AGENTS.md` gains `CLAUDE.md` link parity — `AGENTS.md broken link: AGENTS.md -> <target>` — and a CLAUDE.md import stub whose sibling is missing errors `CLAUDE.md imports @AGENTS.md but AGENTS.md is missing`.
- Portable-project validation is provenance-gated: a hub containing only unsupported Claude artifacts is rejected without migration, while any project-bound `steepy:managed:*:vN` or `steepy:generated:*:vN` artifact
  activates the closed v1 contract. Before project binding, compatibility requires every routed
  single-file or modular core to supply a complete canonical Claude/Codex/OpenCode triad whose bytes
  exactly match the shared `renderProjectArtifact` producer in `scripts/project-scaffold.mjs`. Planner and linter discover portable provenance recursively while expected targets stay canonical. The linter examines every ordinary file in all four provider namespaces — `.agents`, `.claude`, `.codex`, and `.opencode` — irrespective of its name or extension. All recursive provider discovery, including provider presence, reverse agent routing, and skill scans, excludes `node_modules` only when it is an exact directory component and does not inspect that dependency subtree, which is an explicit blind spot. Every near-name directory and ordinary file named `node_modules` remains discoverable, while a symlink named `node_modules` is refused without traversal. Relocated copies/moves activate closed, non-destructive duplicate, wrong-target/orphan, and missing diagnostics. Canonical managed/generated v1 paths resolve to physical ordinary files. The exact repository entries `.apex`, `.agents`, `.claude`, `.codex`, `.opencode`, `AGENTS.md`, and `CLAUDE.md` may be relative or absolute symlink mounts, including external storage. Planner and linter retain logical artifact paths while binding physical targets; recursive provider discovery starts at the bound mount. Broken, cyclic, wrong-type, filesystem-root, and provider/instruction mounts into excluded `.apex/work` are errors. Descendant target symlinks, symlinked ancestors below a mount, target directories/non-files, and non-directory ancestors remain errors; discovery never follows descendant links.
  A root/bootstrap signal or any partial, drifted, mixed, malformed, unresolved, duplicate, relocated,
  or zero-to-two-member sibling set closes validation. In v1, root blocks, bootstrap, stub, routing,
  standards, and adapters form one bijection. Under the v1 single-file producer, active-v1 surface repair accepts only the canonical `standards/<surface>.md` identity with the exact surface title and owner path; modular-only, dual-shape, malformed-title, and owner-mismatch states block before every write. Managed root blocks are standalone or blank-line-separated
  from preserved user prefix/suffix bytes; adjacent placement and a Claude import with other active `@AGENTS.md` targets are `customized` in both planner and linter. Repair adds canonical separation without deleting user bytes and preserves extra import-line bytes inside inert comment prose. An unmarked active Claude import offers `adopt` only as a real `replace-managed` operation: it relocates the active target into the canonical block, preserves every other byte and its LF/CRLF convention, and reruns as an exact no-op. Entirely generated v1 bootstraps and adapters are producer-byte-exact, including LF line endings: CRLF-only drift is `customized` in both the planner and linter, while EOL normalization is reserved for managed blocks whose surrounding user-owned bytes retain their existing LF/CRLF convention. Preparatory identity follows
  the routing row's validated standard target, accepting `standards/<surface>.md` or
  `standards/<surface>/<surface>-core.md` and verifying title plus owning path before exact adapter
  comparison. Once project binding activates, a modular route is a standard/adapter mismatch until
  the shared producer renders routed-core targets. Missing, malformed, unknown-version, customized,
  orphaned, duplicate, wrong-target, or colliding artifacts are errors. The linter remains read-only
  and never supplies a fallback harness.
- Public scaffold repair recognizes only the current canonical v1 artifacts. Noncanonical bytes are ordinary customization conflicts requiring an explicit planner resolution; no prior-format renderer or automatic migration path is available. Repair preserves hub and work bytes and an identical second plan is an exact no-op.
- Codex output inherits by omitting every decoded top-level TOML `model` assignment (bare or quoted, regardless of indentation); model-looking text inside multiline instructions remains content. An unsupported generated `model = "inherit"` is a customization conflict, never an automatic upgrade. Unit coverage does not substitute for native final-payload acceptance evidence.
- Sanitize every external value before writing files (`scripts/sanitize.mjs`); synchronous descriptor writes use `scripts/write-all.mjs`, which advances only on valid positive byte counts, retries short writes, and rejects zero, invalid, or thrown writes.
- `capture-review-evidence.mjs` is the review command-output boundary: it streams completely accepted output to one confined task/loop `evidence-report.md`, hashes/counts only those bytes, emits a bounded receipt, runs surface test → optional Gear-4 verifier → `validate-hub`, replaces stale evidence, and distinguishes a red tested command (receipt with exit 0) from malformed input or capture failure (exit 1). Capture failure starts no later command and enters one awaited path owning detached-group TERM/KILL convergence, independent stream settlement, and exactly one evidence-descriptor close.
- `workflow-state.mjs` is the provider-neutral state kernel: strict versioned event schema and JSONL validation, envelope correlation, attempt/baseline selection, deterministic reducer, shared finite-phase replay, commit-reconciliation classification, and clean-terminal validation; it invokes no harness and reads no Markdown state.
- `loop-engineer.mjs` is the terminal Gear-4 controller: it requires a ratified goal, non-protected branch, clean fresh tree, supported runner, and explicit controller commit authorization, then owns the run lock, sanity verifier, bounded attempt lifecycle, blast-radius check, verifier-driven keep/discard, controller commits, read-only whole-branch review, terminal projections, and crash-safe resume.
- The fresh-run sanity verifier executes before the controller publishes any repository-local lock or machine artifact. A reliable result is followed by the normal repository lock and a repeated branch/clean-tree observation, preserving exclusivity without treating preflight lock residue as exempt repository mutation.
- The append-only event log is Gear 4's sole state authority; every ledger field, including the exact baseline exit and monotonic observability-degradation fact, is reduced from validated events, while the ledger and final diff are projections and never state inputs. Initial `RUN_STARTED` and create-new immutable artifacts are fsynced only after a complete accepted-byte write; partial-prefix or sync errors publish no post-write hook, correlated completion, or success receipt. `ATTEMPT_RESERVED` lands before runner dispatch, create-only evidence, or mutation, so a crash consumes that attempt identity. Resume completes only event- and commit-correlated controller-owned intent. Ambiguity records `RECONCILIATION_REQUIRED`, then `RUN_HALTED`; it never guesses ownership or resets user work. A halt remains `DRAFT`, distinct from clean `GOAL_REACHED`, `BUDGET_EXHAUSTED`, `NO_IMPROVEMENT`, and `REVIEW_REJECTED`; only the first means success, and all require review before `CONSUMED`/`READY` projections. Claude, Codex, and OpenCode have deterministic CLI descriptors; Pi and DeepSeek refuse as `runner-unavailable`. Fake-runner coverage proves the provider-neutral runtime, not five-provider LIVE evidence.
- Goal acceptability follows the retained branch: the baseline initializes it, committed attempts update it, and discarded attempts—including discarded review fixes—leave it unchanged. The same shared derivation drives terminal selection and the terminal candidate receipt.
- A clean terminal event durably binds the reviewer report digest, reviewer diff, final branch-diff projection, and terminal Git snapshot. Read-only validation reopens each physical confined artifact and authenticates its bytes, then proves the current branch, HEAD, clean status, snapshot, and rendered diff still describe the event-derived retained branch before returning facts.
- The real Git adapter exposes crash boundaries between commit `update-ref` and `reset --mixed`, and between discard `reset --hard` and scoped `clean`. Exact prepared-commit metadata and the durable discard snapshot make those intra-command tracked, untracked, and mixed states recoverable after a new process starts; any non-exact state remains ambiguous and is never mutated.
- `RUN_HALTED` is permanently abandoned and not resumable. Its goal, ledger, events, and evidence remain intact; human recovery starts a new ratified goal at a distinct path/workspace rather than deleting or rewriting the halted state. A consumed-goal terminal prefix may still replay the already-recorded halt safely and idempotently.
- The autopilot conductor owns child streams, bounded backpressure, raw-first persistence, and the hybrid failure policy: durable raw-capture failures block, while non-durable observability failures degrade explicitly. Every stop path converges on managed detached-process-group termination, escalation, and verified absence before its final halt/end record.
- Gear-3 autopilot holds one generation-bound physical-checkout lease from locked preflight through terminal recording; proven-dead generations move to retained token-bound quarantine, and release re-verifies generation identity before retirement. The versioned status stream is authority, and only conductor-authored, attempt-correlated `PHASE_ACCEPTED` advances a phase.
- Deterministic process-group ownership in autopilot and review capture is supported only on tested `linux` and `darwin`; other platforms refuse before lease candidates, run-state, or evidence writes. It relies on the operating system's `setsid` process-group/session boundary, not an OS sandbox, and descendants that deliberately escape the spawned group are outside its containment claim; bounded local stream settlement still prevents an escaped inherited-pipe holder from blocking descriptor closure indefinitely.
- The conductor owns deterministic versioned context manifest validation and writes, phase lifecycle, status correlation, artifact timing, and the observational usage ledger. Role-local eager/`onDemand` inventories are manifest data; the implement skill/controller validates artifact-first completion and its selected protocol envelope (manual/legacy v1 four fields; v2 semantic status/artifact/signals). Before review it materializes
  an attributed criteria-only `success-criteria.md`; review rejects a full `.apex/work/specs/**`
  criteria input and consumes canonical `task-result-index.md` plus `branch-diff.txt` artifacts.
  Plan requires the spec, routing index, testing checklist, and implicated routed core/single
  standards. The implement controller eagerly loads only the approved plan; its on-demand inventory
  includes exact ledger/index resume capabilities (present or absent; outputs alone never authorize reads),
  the routing index, exact routed core/single paths, and every leaf named by a core mini-routing table. Task-local manifests require the selected core/single plus matching leaves
  through repeated `--standard` arguments, without guessing a conventional filename or eagerly
  loading unrelated leaves. Phase inventories preserve exact core/leaf order and reachability; the
  plan, implement, and review skill protocols own evidence-based condition matching. This is
  intentional skill behavior, not a claim that the manifest builder deterministically interprets
  human mini-routing conditions. `reviewer-response.mjs` gates Gear-3 reviewer envelopes with versioned evidence, one reserved changed-paths-only correction for protocol 1, frozen reports, and independent Git observations. The conductor replays required task/final receipts before implementation acceptance and resumed review; retained final approvals keep their original provenance and require a pre-dispatch digest plus prior conductor dispatch. Active references update atomically; the full plan is bound except validated status/consumed-by lifecycle fields. The skill owns dispatch; ignored files/transient writes are outside observation.
- Derived review evidence is conductor-derived, never child-reported: the aggregate
  `branch-diff.txt` comes from the run's `BASELINE` commit through `git`, covering committed and
  uncommitted tracked work in one call and naming untracked paths that carry no diff. The baseline
  is recorded once in the status stream, so a resumed run keeps it. What a child still authors it
  verifies first — the same parse the review phase will run is exposed as a check implement runs
  on itself, so a malformed handoff fails where it can still be corrected.
- The conductor reserves each attempt in the append-only status stream before any create-only
  manifest or log write. Resume counts that reservation, so an artifact-preparation crash advances
  to a new immutable attempt path.
- The resource-usage ledger is observational JSONL with direct source provenance: observation
  identity deduplicates exact retransmissions without collapsing distinct measurements, while
  measurement scope independently controls accounting. Phase-scoped measurements without provider
  evidence of disjoint scope must not be summed; reports include only provably disjoint measurements.
  Missing or unsupported scope is unknown, not zero, and an eligibility label is insufficient
  accounting evidence. Unknown-scope observations are retained, and missing-usage completions are durable observations, never zero. Conflicting retransmission evidence is one invalid, non-additive observation and remains in provider-collision analysis. Runtime provider-version evidence gates semantic promotion: OpenCode usage accounting accepts only the provider version verified by `adapters/headless-events.mjs` and `scripts/cost-report.mjs`; missing or different versions stay unknown. This restriction concerns usage accounting, not general OpenCode support. Interactive session-store observations are excluded from additive rollups without official disjoint-scope evidence. There is no work timer or fixed resource stop condition:
  the phase/task topology is finite but a silent live child still requires exit or explicit stop;
  explicit safety/failure conditions, and I/O integrity timeouts for a bounded operation can halt.
- Autopilot and review-evidence I/O route through the `scripts/work-paths.mjs` capability primitive — canonical ordered types `spec | goal | criteria | work-output` (aliases rejected, never normalized) with physical confinement (symlink/non-ordinary/multi-link rejection and device/inode binding), including persistent raw/readable/aggregate/ledger descriptors plus task/loop evidence and review reports — so code and doc never diverge silently.
- Scripts with a real flag schema parse with `node:util`'s `parseArgs` (a built-in) under a
  strict per-CLI schema; `main()` maps a parse throw to the script's usage exit code
  (`new-surface.mjs`, `render-claude-md.mjs`) — two such loops diverged before they were
  consolidated onto `parseArgs`. Scripts that only read a positional dir or a boolean flag or
  two (`validate-hub.mjs`, `detect-stack.mjs`, `stop-hook.mjs`) may read `argv` directly.
  The two usage exit codes differ: `new-surface.mjs` returns 2 on a usage/parse error,
  `render-claude-md.mjs` returns 1 — don't assume they match.
- `project-scaffold.mjs` splits its contract at a tested trust boundary: planning and preview are
  deterministic, frozen, read-only values; validation treats even a planner-shaped plan as
  untrusted and closes its schema, version, IDs, order, paths, prior digests, placeholders,
  provenance markers, minimum adapter syntax, and project/surface triad coherence before apply.
  Planner and validator use the same canonical surface-name/adapter ordering source. Conflicts
  independently use canonical path/ID order and close artifact/path provenance, reason/choice
  pairs, ID/path uniqueness, and operation/conflict disjointness.
- The project-scaffold applicator resolves the physical hub root and supported project mounts,
  preserves mount symlinks by staging/renaming at their physical destinations, rejects descendant symlink/non-file targets or ancestors, aliased operation targets, and stale `priorDigest` state before output writes, and binds every existing ancestor, target, and staged temp by physical device/inode identity. Temp creation and rename run
  relative to a checked parent and recheck bound identities at staged checkpoints. Its concurrency
  threat model covers cooperating project-scaffold writers: after static plan validation and before
  mutable preflight, every mutating project/new-surface transaction atomically publishes one repository-level
  `.steepy-project-scaffold.lock` ownership directory with a closed PID/token record. Contention
  treats only a missing PID (`ESRCH`) as proven stale; a live or unverifiable owner is never stolen
  and fails before scaffold temp or output writes. A dead generation moves atomically to its
  token-bound nonempty quarantine before a successor is published, preventing concurrent stale
  contenders from replacing the live successor. The same ownership is held through preflight,
  parent creation, complete-set staging and validation, every rename, and temp cleanup, then its
  lock and transition residue are released in `finally` on success or handled error. An
  uncooperative process that ignores or tampers with the lock is outside this contract; do not claim
  adversarial-filesystem safety.
  Within the confirmed boundary, the proven behavior is exclusive sibling staging, complete
  staged-set validation, per-file atomic ordinary rename, no multi-file atomicity claim,
  current-file interruption recovery, and timestamp-preserving empty/current no-ops. New-surface standard/routing preflight, complete external staging, planner staging/apply, publication, and cleanup reuse this same lease even when planner operations are empty; only a true full no-op may remain lock-free.
- The project-scaffold CLI accepts only `--hub`, required `--model`, and boolean `--apply`.
  Preview is synchronously emitted as the first JSONL event before any apply; invalid input and
  unresolved conflicts exit 1 without output writes, while preview/no-op/apply success exits 0.
  Diagnostics are bounded and redact authorization, environment, token, and secret-like values. Project `devCommands` are either absent or non-empty, backtick-free safe single-line UTF-8; every surface path uses the shared safe-character grammar (including `@` for scoped package directories) plus canonical non-empty path segments, and every accepted value must normalize/render/parse round-trip. The root-only compatibility boundary is shared by root planning, managed-root parsing, and the current root renderer, so a root pair with zero surfaces remains consumable when `new-surface` adds its first full Project row; the ordinary public Project normalizer remains non-empty. `new-surface.mjs` has two explicit modes: `active-v1` parses the exact canonical Project identity from the managed root, adds or confirms one surface through the full public project planner, accepts only repeatable planner-emitted `--resolution <id=choice>` choices, and makes the managed root, routing row, create-only standard, and adapter triad validator-green before reporting coherence; `preparatory-unbound` retains the bounded standard-plus-triad behavior only when no managed Project identity exists at all. Any present managed Project marker that is unsupported, malformed, duplicate, or otherwise unresolved blocks before every root/routing/standard/adapter write. Repair is create-only for the standard, never guesses a conflict resolution, and a complete rerun preserves bytes, modes, and mtimes.
  Managed Project parsing treats its fixed description slot as data even when it is empty or equals a reserved heading. One root free-text representability check shares the mixed-artifact classifier's managed Project marker grammar, rejects matching markers of every version in the description and each `devCommands` entry before planning, and precedes the normalized root render→parse projection check. Surface `testCmd` values in Project normalization and both `new-surface` modes use `assertSafeTestCommand`: safe single-line UTF-8 is preserved exactly, including ordinary shell quoting/backticks, while a line that CommonMark would treat as the closing backtick fence is rejected. Root projection intentionally omits surface test commands, so parsed existing rows retain the neutral empty command and round-trip comparison excludes source-only command values.
- `live-scaffold-canary.mjs` is the release-evidence driver, not a CI path to real providers. It builds and cleans one planner-backed temporary fixture, uses only `headlessCommand()` for Claude/Codex/OpenCode subprocess descriptors, redacts version/log output, and treats a missing binary or credential as `NOT RUN`. A PASS is derived only from the provider's unique successful terminal event and its final assistant response: that response must parse as exactly `{ lifecycle: "complete", nonces: [root, bootstrap, standard, adapter] }`; tool traces, stderr, duplicate completions, extra fields, and out-of-order values never contribute verification evidence. Pi and DeepSeek remain descriptor-free `runner-unavailable` rows; `all` stays nonzero unless all five ordered rows are `PASS`. Tests may place fake executables only inside their own `mkdtemp` directory. `validate-release-evidence.mjs` provides mandatory product checks and optional release audit verification: it hashes sorted paths, modes, and exact bytes of every `npm pack` product input, excluding exactly docs/native-test-evidence.json, docs/native-test-evidence.md, and docs/release-audit-remediation.md; no documentation directory or path family is excluded. All six records must share one available, HEAD-reachable source commit whose package projection is materialized from committed tree paths, modes, and blob bytes rather than archive output, and whose product inputs have exact path, mode, and byte equivalence with the current product. Commands and UTF-8 artifacts reject unredacted values only in the bounded assignment, flag, Bearer/Basic, credential-header, and cookie forms, accepting an exact whole-value marker `<redacted>`, `[redacted]`, or `REDACTED`; this is not a general secret scanner, so human evidence redaction review remains required. Its `--product-only` mode validates lockstep canonical manifest versions, matching changelog metadata, and absence of an incomplete bump journal. Full manual audit mode additionally requires strict fresh PASS records for plugin preflight and all five native harnesses with the recorded native capability inventory. Records bind source revision, payload/version, host/profile, date, install composition, commands, and a redacted artifact digest. Evidence-only commits preserve product identity; every other shipped-input change invalidates it. The release workflow requires only product mode alongside tests and hub coherence; missing audit evidence never blocks publication. The script never invokes providers, and schema validity documents evidence rather than proving a provider ran.
- `live-scaffold-canary.mjs` rows bind source revision, exact Task11 payload identity, product version, and installation composition before a harness is considered. Its only PASSable record is `descriptor-nonce-response`; it is deliberately an evidence slice, not plugin-load, skill-invocation, scaffold/check, bootstrap, or specialist proof. The native protocol supplies those capability-specific Task11 records. Command-family effects are explicit: the driver creates a temporary fixture, invokes Git and `npm pack --dry-run` to bind product identity, and may invoke a supported provider CLI; missing credentials/binaries remain `NOT RUN`, never a synthetic PASS.
- Autopilot Markdown status accepts UTC timestamps with either whole seconds or exactly three millisecond digits. Whole seconds are normalized to `.000Z` only in memory; source bytes and offsets are preserved. Shared calendar validation and run/attempt/phase acceptance checks remain mandatory. Writers emit `new Date().toISOString()`.

- `source-observation.mjs` separates exact Git source paths from confined work paths, observes branch/HEAD/index/tracked/nonignored-untracked state with NUL-delimited filenames, and refuses unsupported submodules. `task-results.mjs` owns v2 writer begin/capture/inspect/resume/project/verify. Immutable capture, frozen report, and result files publish through staged fsynced atomic writes under the conductor lease. Durable capture can finish publication without redispatch; baseline-only state stays pending. Valid captured NEEDS_CONTEXT/BLOCKED may continue via an explicit retry execution after a concrete remedy; malformed semantics or drift never permit retry. This is not protection from hostile concurrent writers or transient writes.
- The conductor pins TASK_RESULT_PROTOCOL once: fresh runs use 2, legacy retained runs use 1. V2 semantic fields never infer completion from prose; legacy changed-paths is ignored raw telemetry. Receipt-derived JSON arrays preserve source filenames, cumulative per-task paths, and per-execution paths. The latest global parent and same-task previous links establish distinct lineage constraints. Exact state paths recorded before dispatch plus schema-authorized same-directory links permit machine replay only, never work scanning. V2 task approvals bind the latest execution digest; final review and conductor acceptance verify all required task receipts, reports, and approvals, including exact manifest/run/attempt/protocol provenance for every execution ancestor.

## Anti-patterns
- `validate-hub`'s `walk()` is recursive and matches by `basename` only — same-named files in
  different directories collide, and deleting a top-level file won't silence a nested namesake.
- Never `exit 2` from `validate-hub.mjs` — its exits are 0 (ok / no hub) or 1 (violations), and
  process-blocking is owned by the hooks. (CLI usage/parse errors elsewhere, e.g.
  `new-surface.mjs`, legitimately return 2.) The two hook contracts differ: a Stop hook
  **blocks the turn on exit code 2**, so `stop-hook.mjs` signals blocking via the
  `{"decision":"block"}` stdout payload instead and always exits 0; a PreToolUse hook
  blocks on exit 2, so `push-version-guard.mjs` legitimately exits 2 to block a push —
  don't apply one contract to the other.
- Never write an external value to disk unsanitized — route it through `scripts/sanitize.mjs` (path traversal, YAML injection).
- Keep the `import.meta.url` entry guard — without it, importing the module in a test runs `main()`.
- Never `import` `stop-hook.mjs` — it has no entry guard: module load reads stdin and calls
  `process.exit`. It is subprocess-only (`hooks/hooks.json`); test it via `spawnSync`.
- `detect-stack` fatally decodes pnpm workspace UTF-8 and accepts only exact top-level `packages:` block lists or one-line flow lists; unrelated top-level mapping bodies are opaque. Values are non-empty raw-character-admitted, non-typed plain paths or non-empty unescaped quoted paths, and comments require an ASCII space/tab token boundary; it recognizes literal paths, `/*`, and `/**`.
  Other YAML nodes/document forms/key spellings, negation, braces, `?`/`[]`, extglobs, and other glob forms yield `{ inconclusive: true, monorepo: false, surfaces: [] }`, never a confident root-package fallback.
  This is intentionally not a general YAML or glob parser.

## Testing
Narrowest validation that can falsify a change here:

```sh
node --test tests/validate-hub.test.mjs
```

For the portable project planner/applicator and its CLI trust boundary:

```sh
node --test tests/project-scaffold.test.mjs
```
